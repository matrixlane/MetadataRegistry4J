## Why

为系统超级管理员（SUPER_ADMIN）提供高安全性的首次登录免密初始化机制，以及在遗忘密码时的本地应急恢复通道（通过一次性应急登录码）。同时，规范账号管理，限制前台新增管理员，确保系统仅存在唯一的超级管理员。

## What Changes

1. **系统角色限制**：前台新增或编辑用户时，只能选择“普通用户”，禁止创建新的“超级管理员”，确保整个系统仅有唯一的超级管理员。
2. **首次登录免密与强制改密**：超级管理员（admin）首次登录时，无需输入密码即可登录，但登录后必须强制进入改密流程，设置新密码。
3. **本地应急登录码机制**：
   - 系统部署位置下维护一个本地文件（例如 `emergency-code.txt`），用于存放超级管理员的应急登录码。
   - 当忘记密码时，超级管理员可通过该文件中的应急登录码进行临时登录。
   - 应急登录码为一次性的，使用后即被刷新重置。
   - 通过应急登录码登录后，系统强制要求修改密码，且新密码不能与旧密码相同。
4. **超级管理员自身保护机制**：超级管理员不能禁用或删除自己的账号，只能管理其他普通用户的账号状态。
5. **用户列表展示优化**：在用户管理列表中，新增“上次登录时间”列，方便监控各账号的活跃状态。
6. **允许自主注册控制开关**：在系统设置中提供全局开关以启用/禁用“允许注册新用户”功能，此开关默认开启。若关闭，登录页面的自助注册入口应当隐藏，且注册 API 将拒绝新注册请求。
7. **普通用户密码重设机制**：超级管理员可以对普通用户账户进行“重设密码”操作，系统将生成一个随机临时密码并仅展示一次。此临时密码只能用于成功登录一次，且登录后系统将强制用户进入改密流程。

## Capabilities

### New Capabilities
- `admin-emergency-login`: 包含超级管理员的首次免密登录强制改密逻辑，本地应急码生成、验证、刷新和强制修改密码机制，以及超级管理员账号的安全自保校验，并提供超级管理员对普通用户的“重设密码”及单次登录强制改密机制。

### Modified Capabilities
- `user-self-registration`: 包含在用户管理中限制只可创建“普通用户”角色、用户列表中新增“上次登录时间”列展示，以及在系统设置中增加并控制“允许自主注册”全局开关的逻辑。

## Impact

1. **后端 API & 安全过滤**：
   - 登录 API：需要支持应急登录码的验证和首次免密登录逻辑；支持普通用户使用临时重置密码登录及单次登录拦截。
   - 改密 API：超级管理员或处于强制改密状态的普通用户改密时，校验相应状态并在成功后清除强制状态。
   - 账户管理 API：删除、禁用、更新接口需在后端校验，禁止操作超级管理员自身账号；新增“重置普通用户密码”的 POST 接口，仅限超级管理员调用。
   - 系统配置 API：新增获取和更新“允许自主注册”开关状态的接口。
   - 文件系统：系统需要读取并写入部署目录下的本地文件以维护应急登录码。
2. **前端 UI**：
   - 登录页面：超级管理员首次登录免密或使用应急登录码登录时的交互逻辑；根据“允许自主注册”开关状态显示或隐藏注册按钮。
   - 强制改密弹窗/页面：在登录成功后，若检测到是首次登录、应急码登录或临时密码重置登录，强制弹出改密界面，且不修改密码无法进行其他操作。
   - 用户管理页面：限制只可选“普通用户”角色；增加“上次登录时间”列；对当前登录账户自身的“禁用”和“删除”操作按钮进行禁用或隐藏；增加针对普通用户的“重置密码”操作按钮，并在重置成功后弹窗展示一次性随机密码。
   - 系统设置页面：新增“允许注册新用户”配置开关，支持超级管理员在线调整。
