## Context

Metadata Registry 在经过多轮测试、演示或开发周期后，数据库中会积累大量脏数据。当前版本没有提供快速重置机制，开发与实施人员只能通过重建数据库或手动执行 SQL 脚本来清空数据。由于系统表多达 50 余张且外键依赖复杂，手动清空效率极低且容易出错。

本设计提出在系统管理中引入“恢复出厂设置”功能，允许超级管理员通过输入密码进行身份验证后，由系统自动、安全、有顺序地擦除所有配置和业务数据，并将系统状态恢复至首次部署未初始化的状态。

## Goals / Non-Goals

**Goals:**
- 提供高安全性的“恢复出厂设置” API 接口与前端交互界面。
- 采用动态数据库元数据查询，按约束关闭、擦除、重置、恢复的生命周期清空除 Flyway 迁移历史表之外的所有表数据。
- 重置后保留且仅保留唯一的初始默认超级管理员账号（`admin / Admin@123`），并重置其用户 ID（UUID）。
- 重置系统初始化状态为 `false`，确保下次访问时强制进入初始化向导。
- 自动失效当前持有的 JWT 令牌，防止后续未经授权的请求。

**Non-Goals:**
- 不支持部分数据清理（如仅清空业务数据保留用户配置，本功能为完全清空）。
- 不支持物理删除或清空数据库 Schema 本身，也不重新执行 Flyway 迁移脚本（保留表结构）。

## Decisions

### 1. 数据库清空策略：动态禁用外键约束 + DELETE FROM
* **方案 A**：硬编码拓扑排序的删除语句（`DELETE FROM table_a; DELETE FROM table_b; ...`）。
  * 缺点：可维护性极差。后续开发新增表时，若忘记更新此处的删除顺序，将直接导致外键约束冲突而清空失败。
* **方案 B**：使用临时禁用约束的动态 SQL（**选择此方案**）。
  * 步骤：
    1. 查询 `sys.tables` 获取所有非 `flyway_schema_history` 表。
    2. 执行 `ALTER TABLE [tableName] NOCHECK CONSTRAINT ALL` 禁用所有外键约束。
    3. 循环执行 `DELETE FROM [tableName]` 清空数据（因 Truncate 会受外键定义限制，即使 NOCHECK 也会报错，因此必须用 DELETE）。
    4. 执行 `DBCC CHECKIDENT ('tableName', RESEED, 0)` 重置自增主键。
    5. 执行 `ALTER TABLE [tableName] WITH CHECK CHECK CONSTRAINT ALL` 重新启用并校验外键约束。
  * 理由：通用、高内聚且自适应未来表结构的扩增，保证了系统的强健性。

### 2. 会话/令牌失效机制：自然失效（User UUID 变更）
* **方案 A**：引入 Redis 或内存黑名单记录失效的 JWT。
  * 缺点：增加系统复杂度，破坏了无状态 JWT 的设计原则。
* **方案 B**：利用用户 ID 变更自然失效（**选择此方案**）。
  * 机制：由于恢复出厂设置清空了 `app_user` 表，重新创建的 `admin` 超级管理员会被分配一个新的随机 UUID。原 JWT Token 中的 `sub` 声明对应的旧 UUID 在数据库中不再存在，后续 API 请求在 JWT 校验阶段尝试加载用户时会直接报 `401 Unauthorized`，实现瞬时会话失效。

### 3. 前端界面控制与防误操作
* **UI 交互**：在系统管理页面底部的危险区域提供“恢复出厂设置”操作。
* **双重验证**：点击后显示醒目的红色二次确认弹窗，并要求管理员输入其当前的登录密码。仅当密码通过后端比对校验后才触发擦除逻辑。
* **状态阻断**：擦除请求发起后，前端显示全屏不可取消的 Loading 遮罩，成功后自动清除 Pinia 状态并路由至 `/init-wizard`。

## Risks / Trade-offs

- **[Risk] 数据库锁与并发**：如果在执行清空期间有其他活跃会话在写入数据，可能导致锁冲突或清空不彻底。
  - **Mitigation**：此操作仅超级管理员可执行，应在系统维护期进行。执行时将调用 SecurityContext 废弃其他会话，且擦除属于单线程事务块运行。
- **[Risk] 重置失败导致数据库处于半清空状态**：中途报错可能导致部分表已删，部分未删。
  - **Mitigation**：整个擦除与重建默认 admin 账号的过程封装在同一个 Spring `@Transactional` 事务内，确保要么完全成功，要么完全回滚。
