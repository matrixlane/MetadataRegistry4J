## Why

初始化向导目前保存数据源配置后要求用户手工重启应用，非技术用户需要理解并操作后端进程，且重启期间没有可靠进度或失败恢复。目标是在已确认的 Windows 单机个人版启动器场景下，让系统自动完成重启、数据库准备、配置核对与失败回滚，并向用户展示可理解的连续进度。

## What Changes

- 新增常驻 Windows 后端启动器，托管明确的数据源重启事务：等待旧进程退出、启动目标配置、检查完整就绪状态，并在失败或超时时恢复旧配置。
- 新增数据源自动重启能力查询、“保存并自动应用”和重启状态查询接口；自动应用包含配置备份、并发保护、本机访问限制和实际运行配置核对。
- 初始化向导在受支持的启动方式下自动应用数据源配置，展示保存、重启、数据库准备、验证与恢复阶段；支持刷新后恢复等待，并避免重启期间误调用初始化 `abort`。
- 新配置无法启动时自动恢复旧配置并返回可编辑的数据源步骤；恢复失败提供非技术化的重试与支持指引。
- 不受启动器托管的启动方式保留原手工重启流程；系统设置中的数据源页面与既有 `PUT /api/v1/datasource/config` 行为不变。
- 启动与停止脚本协调停止信号，防止用户主动停止应用后又被启动器自动拉起。
- 不修改数据库表结构、ISO/IEC 11179 元模型、三方方言迁移脚本或既有启动就绪探针契约。

## Capabilities

### New Capabilities

- `application-restart-supervision`: 定义 Windows 单机个人版常驻启动器的进程托管、重启事务状态、完整就绪与目标配置核对、启动超时、旧配置自动恢复、停止信号及敏感信息保护。

### Modified Capabilities

- `datasource-configuration`: 将“保存后只能引导手工重启”扩展为受管初始化场景可自动应用，规定配置备份、自动应用接口、重启状态与不受管环境的兼容行为；系统设置页仍维持手工重启。
- `system-initialization`: 规定初始化向导在自动重启期间的阶段进度、重复提交保护、刷新恢复、初始化放弃语义例外，以及成功或回滚后的继续流程。

## Impact

- **后端**：`DatasourceConfigController`、`DatasourceConfigService` 及新增自动重启服务/DTO、退出执行抽象与重启状态模型；复用 `DatabaseEnvironment` 和 `/api/v1/startup/status`。
- **前端**：`InitWizard.vue`、新增重启进度/轮询模块及相应 Vitest；复用现有静默启动探测模式，不新增依赖。
- **启动脚本**：`start.bat`、`stop.bat`，新增 `scripts/backend-supervisor.ps1`；使用现有 JDK、PowerShell 与项目 JAR。
- **API**：新增能力查询、自动应用和重启状态端点；既有数据源配置端点保持兼容。
- **文档与验证**：更新 README 和必要的架构说明；补充后端、前端、PowerShell 语法及隔离环境真实进程端到端验证。
