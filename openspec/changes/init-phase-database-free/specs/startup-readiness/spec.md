## MODIFIED Requirements

### Requirement: 就绪探针端点

系统 SHALL 提供匿名端点 `GET /api/v1/startup/status`，响应体为统一 `ApiResponse` 包装的对象，含 `ready` 布尔字段。`ready=true` 当且仅当应用启动全部阶段完成（含所有数据初始化 Runner）；启动完成前该端点 MUST 可达且返回 HTTP 200、`ready=false`。就绪状态 MUST NOT 在进程生命周期内回退。当数据库初始化引导失败时，端点 SHALL 额外返回失败信息（失败阶段、原因码与可读描述），使调用方能够区分"仍在启动"与"初始化失败"。失败信息 MUST NOT 包含数据库口令或完整连接串。

#### Scenario: 启动完成前查询

- **WHEN** 应用正在启动（Web 层已监听但初始化 Runner 未完成，或任何可响应状态）
- **THEN** 端点返回 HTTP 200 且 `data.ready=false`

#### Scenario: 启动完成后查询

- **WHEN** `SpringApplication.run()` 全部阶段完成
- **THEN** 端点返回 HTTP 200 且 `data.ready=true`

#### Scenario: 匿名访问

- **WHEN** 未携带任何认证信息请求该端点
- **THEN** 返回 HTTP 200（不返回 401/403）

#### Scenario: 初始化失败时暴露原因

- **WHEN** 数据库初始化引导失败
- **THEN** 端点返回 HTTP 200 且 `data.ready=false`，并携带失败阶段、原因码与可读描述

### Requirement: 前端启动等待界面

前端 SHALL 在应用挂载前探测后端就绪。未就绪期间，界面 MUST 显示全屏启动等待界面（含品牌标识、启动中提示与不确定态加载动画），MUST NOT 发起任何业务 API 请求，MUST NOT 显示"服务器内部错误"类错误提示。后端已就绪时，等待界面 MUST NOT 对用户可见闪现（就绪场景下探测与挂载完成前等待界面尚未浮现）。后端报告初始化失败时，界面 MUST 切换为失败状态，展示"初始化系统失败"与可读原因，并提供重试初始化与退出应用两个动作。

#### Scenario: 后端未就绪时打开网站

- **WHEN** 后端尚未就绪时用户打开前端任意页面
- **THEN** 用户看到启动等待界面，页面无任何错误提示，且不产生业务 API 请求

#### Scenario: 就绪后自动进入

- **WHEN** 探测到 `ready=true`
- **THEN** 等待界面被移除，应用进入既有流程：系统未初始化进入初始化向导，未登录进入登录页，已登录进入目标页

#### Scenario: 初始化失败时展示原因与动作

- **WHEN** 后端报告数据库初始化失败
- **THEN** 界面展示"初始化系统失败"与可读原因，并提供重试初始化与退出应用两个动作

### Requirement: 长时间未就绪提示

等待后端就绪超过 60 秒时，等待界面 MUST 显示排查提示（指引检查后端启动窗口）与重试入口（刷新重探测）。若后端已明确报告初始化失败，等待界面 MUST 显示失败原因与可恢复动作，MUST NOT 继续按"仍在启动"无限等待。

#### Scenario: 后端启动失败或极慢

- **WHEN** 等待超过 60 秒仍未就绪
- **THEN** 等待界面显示排查提示与重试按钮；点击重试后重新开始探测

#### Scenario: 已知失败原因时不无限等待

- **WHEN** 后端报告数据库初始化失败且携带原因
- **THEN** 等待界面显示该原因与重试初始化、退出应用两个动作，MUST NOT 仅显示"仍在启动"
